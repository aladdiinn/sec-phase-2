BUG 3 — MANAGED SERVICES (RESTART LOGIC) NOT SAVING
SERVICE CONFIGURATIONS NOT PERSISTED + PLAYBOOK INTEGRATION BROKEN
🔴 BUGASSET DETAIL — MANAGED SERVICES
SERVICE CONFIGURATIONS NOT SAVING TO DATABASE
The "Managed Services (Restart Logic)" section (Image 2) lets you configure services like Tomcat with Name, User, Binary Path. But these configs are NOT being saved — same root cause as maintenance toggle: no API call on form submit. The "RUN RESTART PLAYBOOK" button also fails because there are no saved services to restart.
IS MANAGED SERVICES REQUIRED?
YES — absolutely required. Without it, the "Restart Service" playbook action has NO way to know: which service to restart, what the binary path is, which Linux user to run it as, or what the server's service name is. This config IS the bridge between your playbook and the real server.

Example: You run Tomcat as user "tomcat8" from /app/apache-tomcat/bin/startup.sh. Without this config, a playbook cannot automatically restart it.
WHAT THE CONFIG ENABLES
Once services are saved:
• Playbook "RESTART SERVICE" action can select from the saved services list for that server
• Agent receives restart command: {service_name, binary_path, run_as_user}
• Agent executes: sudo -u tomcat8 /app/apache-tomcat/bin/startup.sh
• Agent reports back: success/failure with stdout/stderr
• Alert is auto-resolved if restart succeeds
// BUG FIX 3 — MANAGED SERVICES SAVE + PLAYBOOK INTEGRATION
