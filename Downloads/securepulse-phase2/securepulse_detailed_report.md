## 1. Visible Dashboard Features
The following features are fully accessible and functional within the current UI.

### 🔍 Detection & Alerting
- **Real-Time Event Correlation (#01)**
  - **Logic**: Backend `ingest_event` handles real-time intake.
  - **Internal Working**: Every incoming event is processed through a rule manager that checks for keyword matches (e.g., "sudo") and specific patterns.
  - **Real-World Scenario**: A developer mistakenly runs `chmod 777` on a sensitive directory; an alert triggers instantly.
- **Rule-Based Alerting (#03)**
  - **Logic**: Defined in `rules/default_rules.yaml`.
  - **Location**: `/rules` page.
  - **Internal Working**: Uses YAML signatures for regex and string matching.
- **Threat Intelligence Feeds (#05)**
  - **Logic**: Real-time IP matching against `threat_indicators` table.
  - **Internal Working**: Extracts IPs from event descriptions and raw data, then queries the TI database.

### 🚨 Incident Management
- **Incident Queue & Triage (#07)**
  - **Location**: `/incidents` (alerts.html).
  - **Internal Working**: Fetches unresolved alerts from `models.Alert` and sorts them by severity.
- **Case Management (#08)**
  - **Logic**: Grouping related alerts into a `Case`.
  - **Location**: `/investigate/<case_id>`.
  - **Internal Working**: Analyst promotes an alert to a case, creating a record in the `cases` table.
- **Workflow Automation (SOAR) (#10)**
  - **Logic**: `PlaybookRunner` class in `app.py`.
  - **Internal Working**: Executes predefined JSON actions (e.g., "isolate_host") when triggers are met.

## 3. Technical Breakdown

### Frontend (HTML/CSS/JS)
- **Base Layout**: `templates/base.html` (Glassmorphism design).
- **Visualization**: `D3.js` for the topology graph in `investigation.html`.
- **Real-Time**: `Socket.IO` for live event pushing.

### Backend (Python/Flask)
- **Primary Logic**: `app.py` handles routing, event ingestion, and rule evaluation.
- **Authentication**: JWT for API endpoints, Session-based for frontend pages.
- **RBAC**: Three roles defined in `models.py`: `superuser`, `admin`, `normal`.

### Database (PostgreSQL)
- **Core Tables**: `users`, `servers`, `events`, `alerts`, `cases`, `audit_logs`.
- **Relationship**: `Alert` has a foreign key to `Event` and `Case`. `Server` (Asset) links to all events/alerts.

## 4. Real-Time Behavior Analysis
- **Is it real-time?**: Yes, truly real-time for UI updates via WebSockets.
- **Update Triggers**: Incoming agent events trigger the `new_event` Socket.IO emission.
- **Refresh Rate**: Dashboard stats refresh every 5 seconds or upon WebSocket event.
- **Failure Mode**: If an agent is down, the `heartbeat` event stops, and the server status changes to "Offline" after a 120s timeout.

## 5. Security & Architecture Analysis
- **Auth Flow**: Analyst Login → Session/JWT created → Page access granted based on Role.
- **Role-Based Access**:
  - `superuser`: Can manage users, SSO, and DR tests.
  - `admin`: Can isolate hosts and create detection rules.
  - `normal`: Can triage incidents and investigate cases.
- **Missing Validations**: Need stricter input sanitization on `raw_data` JSON blobs.
